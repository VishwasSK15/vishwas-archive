Product Requirements Document (PRD)
Document Type: Product Requirements DocumentProduct: Personal Portfolio / Digital ArchiveOwner: Vishwas S KStatus: Active / Iterative BuildPrimary Goal: Create a distinctive personal portfolio that feels like a curated digital archive rather than a conventional developer portfolio.
1. Product Overview
1.1 Product Name
VISHWAS // THE ARCHIVE
The portfolio is designed as a digital archive of Vishwas's work, interests, creative identity, technical capabilities, and visual interests.
It should communicate:
A person with multiple creative and technical worlds, presented through one cohesive editorial experience.
The site is not intended to look like a conventional "developer portfolio" containing a hero, skill cards, project cards, and contact section.
Instead, it should feel closer to:
a personal digital archive
an editorial website
a cinematic experience
a curated exhibition
a visual identity system
The design should be memorable because of its composition, typography, navigation, transitions, imagery, and storytelling, rather than because of excessive visual effects.
2. Product Vision
Create a portfolio that answers three questions immediately:
Who is Vishwas?
A developer and creative individual whose interests extend beyond coding.
What does Vishwas do?
Builds software while also exploring:
photography
image/video editing
automobiles
cinema
visual storytelling
What makes the portfolio different?
Instead of presenting everything as one list, the portfolio divides the identity into distinct worlds.
The user should feel that they are navigating an archive rather than browsing a resume.
3. Core Product Philosophy
The portfolio should follow five principles.
3.1 Editorial, not generic
Avoid the visual language of generic AI-generated portfolios.
The design should feel intentionally art-directed.
3.2 Content before decoration
Visual effects should support the content.
They should never become the content.
3.3 Real over fabricated
Use real projects, real repositories, real photography, real personal imagery, and real interests.
Do not invent:
achievements
statistics
clients
experience
projects
skills
testimonials
professional claims
3.4 Distinct worlds, unified identity
Each section should have its own atmosphere and visual character while still belonging to the same portfolio.
3.5 Cinematic but restrained
The site can have motion and transitions, but it must avoid becoming an effects showcase.
4. Target Experience
A visitor should experience the site roughly like this:
INTRO → IDENTITY → WORLDS → EXPLORE → ARCHIVE → ABOUT → EXIT
The homepage establishes the identity.
The individual worlds provide depth.
Navigation allows the visitor to move through the archive naturally.

20. Color System
The original direction experimented with multiple colors, including blue, gold, and light red.
The design evolved toward stronger hue separation between worlds, rather than making the entire site predominantly blue.
The current philosophy is:
Use color to distinguish worlds and establish atmosphere, not to decorate every component.
21. Homepage Color Direction
The homepage should use:
warm neutral / near-white light background
dark readable text
one restrained accent
Dark mode must be a genuine dark theme rather than simply making the light theme black.
22. Accent Color
A later design direction established that the accent should be derived from the blue tone visible in the user's shirt in the selected reference image.
This replaces the previous green accent direction.
Where the old design used green accent elements, those areas should use the chosen blue accent instead.
The accent should be applied consistently to:
selected UI elements
highlights
borders where appropriate
active states
key visual details
It should not flood the interface.

Motion is important, but should remain purposeful.
Use animation for:

Animation should communicate:

28. Reduced Motion
The product must respect user motion preferences.

31. Real Image Strategy
Real images are a core part of the portfolio.
Where a personal image is required:
use the actual supplied image
crop appropriately
remove the background when required
preserve the subject's identity
avoid AI-generated replacement subjects
The visual treatment should enhance the actual photograph rather than replace it.
32. Image Treatment
For hero/cutout compositions:
start with the user's actual image
crop appropriately
remove the background naturally
place the subject behind/inside selected typography
integrate the image into the composition
apply restrained color treatment where necessary
Do not turn the subject into an artificial glowing object.

55. Development Principles
As a senior indie-development project, implementation should follow:
1. Build the system, not individual screens
Components and design tokens should be reusable.
2. Preserve the visual language
New pages must belong to the same archive.
3. Prefer composition over decoration
Solve visual problems through:
typography
spacing
layout
imagery
hierarchy
before adding effects.
4. Prefer native capabilities
Do not add a library when the current stack can handle the requirement cleanly.
5. Keep data dynamic where it matters
Especially GitHub/project data.
6. Keep personal content editable
Content should not be deeply buried inside components.
